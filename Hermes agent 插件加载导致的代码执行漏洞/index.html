0.9版本

二、代码审计分析过程

文件 hermes_cli/memory_setup.py:126-140：

check_cmd 来自 plugin.yaml 中 YAML 解析后的字符串，未经任何过滤直接传入 subprocess.run(shell=True)，等价于在系统 shell 中执行任意命令

触发链条与前置条件分析

文件 hermes_cli/memory_setup.py:65-66 ：

有一个plugin.yaml

文件 hermes_cli/memory_setup.py:75-77 ：

plugin.yaml 中必须声明至少一个 pip_dependencies 条目。如果缺失或为空列表，函数在此处返回，external_dependencies 完全不会被处理

文件 hermes_cli/memory_setup.py:87-87 ：

至少一个 pip 依赖未安装

通过上述三步后函数尝试 uv pip install 安装缺失依赖，只要系统安装了 uv（hermes-agent 的标准依赖管理工具），无论安装成功还是失败，函数都不会 return，而是继续执行到第 127 行的 external_dependencies 处理逻辑

恶意插件被自动发现的条件（plugins/memory/init.py:32-75）：

位于 plugins/memory/ 目录下

是目录且名称不以 _ 或 . 开头

包含 init.py

init.py 有 register(ctx) 或 MemoryProvider 子类
